Este anexo reúne la información necesaria para auditar los resultados, reconstruir los experimentos cuando se dispone de los datos de origen y ejecutar la aplicación. El repositorio conserva el código, las configuraciones, los manifiestos, las métricas y las figuras. Las capturas del taller y los activos gráficos empleados para crear el conjunto sintético no se publican, ya que contienen material de trabajo facilitado para este proyecto. Esta limitación no afecta a la inspección de los resultados conservados, pero impide regenerar las imágenes desde un clon público sin incorporar primero esos archivos.

\section{Estructura principal}

\begin{description}
    \item[\texttt{memoria/}] Fuentes \LaTeX, bibliografía y material gráfico.
    \item[\texttt{software/}] Aplicación, interfaz, configuración y pruebas automáticas.
    \item[\texttt{datos/}] Manifiestos y, en la copia de trabajo autorizada, imágenes y anotaciones.

    \item[\texttt{resultados/}] Métricas CSV y JSON, figuras, máscaras de salida y evidencias DXF.
    \item[\texttt{documentacion/}] Protocolo, controles de calidad y guía de las evidencias cuantitativas.
    \item[\texttt{output/pdf/}] Memoria compilada.
\end{description}

El archivo \path{datos/manifiesto/asset_registry_v2.csv} identifica los 32 activos fuente. \path{datos/manifiesto/datasets_asset_identity_v2.csv} describe las 48 hojas generadas y \path{resultados/metricas/dataset_identity_v2_quality.json} registra las comprobaciones de independencia. \section{Entorno de ejecución}

El entorno utilizado en la evaluación final fue Windows con Python 3.12.10, PyTorch 2.13.0+cpu, OpenCV 4.14.0 y scikit-learn 1.9.0, versiones que quedan registradas en los resúmenes de ejecución. Los archivos de requisitos instalan un entorno compatible, aunque no constituyen por sí solos un bloqueo exacto de todas las dependencias transitivas. La preparación se realiza desde la raíz del repositorio:

\begin{verbatim}
python -m venv .venv
.\.venv\Scripts\Activate.ps1
python -m pip install --upgrade pip
pip install -r requirements-core.txt
pip install -r requirements-ai.txt
\end{verbatim}

La dependencia \texttt{sam-2} está fijada a una revisión concreta del repositorio oficial de Meta en \path{requirements-ai.txt}. De esta forma, la instalación no depende de la versión más reciente disponible en el momento de repetir el experimento. El checkpoint esperado se guarda como \path{resultados/modelos/sam2_hiera_tiny.pt}.

\section{Secuencia de reproducción}

Tras disponer de un directorio autorizado que contenga los 32 activos fuente, la preparación y auditoría del conjunto se ejecutan con:

\begin{verbatim}
python experimentos/datos/prepare_source_assets.py `
  --source-dir "RUTA_AUTORIZADA"
python experimentos/datos/generate_identity_disjoint_dataset.py
python experimentos/datos/audit_identity_disjoint_dataset.py
python experimentos/datos/test_identity_disjoint_dataset.py
\end{verbatim}

El entrenamiento separa deliberadamente selección y prueba. En una reproducción limpia se usa el orden siguiente:

\begin{verbatim}
python experimentos/random_forest/train_rf_identity_v2.py select
python experimentos/random_forest/train_rf_identity_v2.py ablate
python experimentos/random_forest/train_rf_identity_v2.py test
python experimentos/random_forest/evaluate_rf_identity_v2_real.py
python experimentos/random_forest/analyze_rf_identity_v2.py
\end{verbatim}

El comando \texttt{select} trabaja con entrenamiento y validación, mientras \texttt{test} comprueba los hashes del bloqueo y se niega a sobrescribir una evaluación ya realizada. Esta separación evita que el conjunto de prueba intervenga en la elección del modelo.

La evaluación de SAM 2, la línea base y la cadena geométrica se reconstruye con:

\begin{verbatim}
python experimentos/comparacion/validate_real_reference.py
python experimentos/comparacion/evaluate_classical_identity_v2.py
python experimentos/sam2/select_prompt_margin_identity_v2.py --device cpu
python experimentos/comparacion/benchmark_segmentation_runtime.py `
  --device cpu
python experimentos/comparacion/benchmark_idv2_final_runtime.py
python experimentos/geometria/evaluate_wcs_repeatability.py
python experimentos/geometria/generate_wcs_detection_stages.py
python experimentos/comparacion/run_integration_batch.py --device cpu
python experimentos/comparacion/generate_final_idv2_figures.py
python experimentos/comparacion/generate_protocol_figures.py
python documentacion/regenerar_figuras_legibles_adicionales.py
python experimentos/comparacion/verify_protocol_package.py
python -m unittest discover software/tests -v
\end{verbatim}

SAM 2 se utiliza preentrenado y sin ajuste fino. La selección se limita al margen de las cajas propuestas por el localizador y se resuelve en validación. Las cifras reales se calculan después del bloqueo y expresan concordancia con una referencia canónica asistida, no exactitud frente a una verdad de terreno independiente.

\section{Aplicación y pruebas}

La interfaz se abre con:

\begin{verbatim}
python software/src/gui.py
\end{verbatim}

La configuración efectiva se encuentra en \path{software/config/default.yaml}. La ruta operativa usa SAM 2 para producir la máscara que llega a la vectorización. Si falta el checkpoint o el modelo no puede inicializarse, la aplicación informa el error y no sustituye la salida por otra técnica. La exportación también permanece bloqueada cuando no se ha procesado una imagen, el WCS no es válido o no existen trayectorias.

Las pruebas automáticas se ejecutan con:

\begin{verbatim}
python -m unittest discover software/tests -v
\end{verbatim}

Estas pruebas cubren la configuración, los estados de la aplicación, la detección WCS, la extracción de siluetas exteriores y la escritura y reapertura del DXF. Son controles de software y geometría que no sustituyen una validación física del corte.
